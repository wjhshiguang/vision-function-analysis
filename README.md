# 视功能自动分析工作台

眼镜店 / 视光师专用工具：录入视功能检查数据 → 自动分析 → 生成报告 → 管理复查提醒。

## 功能

- **检查录入**：屈光、调节（NRA/PRA/BCC/AMP/调节灵敏度）、双眼视（隐斜/融像/AC-A/集合近点）分组录入，数值字段为滚轮选择器
- **自动分析**：按指标准则判定异常、交叉诊断、严重度分级
- **报告生成**：结构化报告，可复制为文本
- **复查管理**：自动生成复查日期，「今天要处理」置顶逾期项
- **顾客档案**：全部记录检索与回溯

## 符号约定

- PRA 记录为**负值**，绝对值越大越好
- **外隐斜记为负值**，内隐斜记为正值

## 数据说明

所有数据仅保存在**使用者本机浏览器**（localStorage），不上传任何服务器。
建议定期使用页面内的「导出 JSON 备份」保存数据。

## 使用

打开 GitHub Pages 链接即可使用。手机端可通过浏览器「添加到主屏幕」获得全屏 App 体验。

## 技术

单文件 HTML，CSS/JS 全内联，零外部依赖；PWA（manifest + Service Worker）支持离线打开。

## 登录门禁（手机号 + 邀请码）

本工具已加一层**访问门禁**：打开链接后必须先输入**手机号**与**邀请码**才能进入，无邀请码无法使用。首次输入即完成"注册"（登录态保存在本机浏览器，下次打开免输）。侧边栏底部有「退出登录」。

**管理员（门店）如何发放 / 管理邀请码：**
- 邀请码写在 `index.html` 里的 `AUTH_CONFIG.inviteCodes` 数组中（默认 `SHIGUANG2026`、`JINGGONG888`）。
- 增删改邀请码后，重新部署（`git push`）即生效。
- 想换一批人用：改掉旧码、加上新码，再推送即可"作废"旧码（旧码用户下次打开会被拦）。
- 想踢人：让对方「退出登录」，并作废其持有码。

> ⚠️ **这是"软门禁"，不是真安全。** GitHub Pages 是纯静态托管，邀请码会明文出现在网页源码里，懂技术的人查看源码即可拿到。它用来挡住普通用户、让你掌控谁能进，但**无法真正防盗用**。

## 升级路径（真·防盗用）

要"所有人能打开、但你真正掌控、手机号+邀请码、可随时撤销某人"，必须让校验发生在**服务器/云端**，而不是浏览器里。以下是从 GitHub 上挑选的、社区热度与安全性都很高、可直接接入的鉴权系统（均需要服务器，届时部署方式会由"纯 GitHub Pages"改为"带后端的托管"）：

| 系统 | GitHub 仓库 | 适合场景 |
|---|---|---|
| **Supabase Auth** | `supabase/supabase` | 开源 BaaS，原生支持手机号+密码/验证码，邀请码与用户可在后台随时撤销、禁用。**最契合本工具。** |
| **Clerk** | `clerk/clerk-js` | 托管式鉴权，手机号/邀请码开箱即用，后台可精细化管理用户。 |
| **Firebase Authentication** | `firebase/firebase-js-sdk` | Google 托管，手机号 SMS 验证码校验成熟稳定。 |
| **Authelia** | `authelia/authelia` | 自托管 SSO/2FA 网关，挡在整个站点前面，适合反向代理保护。 |
| **OAuth2 Proxy** | `oauth2-proxy/oauth2-proxy` | 反向代理层加登录，任何站点前面都能套一层登录。 |

**推荐下一步**：告诉我"升级到真·后端登录"，我会把 **Supabase Auth** 接进本页面——邀请码与手机号在云端校验、你可随时撤销某个用户/某个码，彻底杜绝源码泄露导致的盗用。部署会改用带后端的托管方式（链接不变或平滑切换）。
